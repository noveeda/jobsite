# 기능 명세: 개인용 통합 채용공고 허브

**기능 식별자**: `001-job-posting-hub`
**작성일**: 2026-08-06
**상태**: 초안 완료
**목표 단계**: 개인용 MVP

## 1. 개요

사람인, 잡코리아, 잡플래닛, 기업 채용 페이지 등 여러 출처에서 발견한 채용공고를 한곳에 모아 일관된 형식으로 탐색하고, 중복 공고를 구분하며, 관심 여부와 지원 진행 상태를 관리할 수 있는 개인용 웹 도구를 만든다.

초기 제품은 한 명의 사용자가 자신의 구직 활동을 관리하는 데 집중한다. 여러 사용자가 가입하는 공개 서비스, 모든 채용 사이트에 대한 전면 자동 수집, 기업 리뷰와 연봉 데이터의 자체 제공은 MVP 범위에서 제외한다.

## 2. 해결하려는 문제

- 채용공고가 여러 사이트에 흩어져 있어 반복 검색이 필요하다.
- 동일한 회사와 직무의 공고가 여러 출처에 중복 게시된다.
- 공고마다 표현 방식이 달라 조건을 빠르게 비교하기 어렵다.
- 이미 검토한 공고, 제외한 공고, 지원한 공고를 기억하거나 별도 문서로 관리해야 한다.
- 마감일과 지원 후속 일정을 놓치기 쉽다.

## 3. 제품 목표

1. 사용자가 여러 출처에서 발견한 공고를 하나의 목록으로 관리한다.
2. 공고 핵심 정보를 동일한 기준으로 보여주어 비교 시간을 줄인다.
3. 동일하거나 매우 유사한 공고를 묶어 중복 검토를 줄인다.
4. 관심 공고부터 지원 결과까지 개인의 지원 흐름을 기록한다.
5. 향후 자동 수집과 다중 사용자 서비스로 확장할 수 있도록 제품 개념과 데이터 경계를 명확히 한다.

## 4. 범위

### 4.1 MVP 포함 범위

- 채용공고 원문 URL 등록
- URL에서 가져올 수 없는 공고의 수동 등록 및 수정
- 공고 핵심 정보의 표준화된 표시
- 목록 검색, 필터, 정렬
- 유사·중복 가능성이 있는 공고 표시 및 묶음 조회
- 관심, 제외, 지원 진행 상태 관리
- 개인 메모와 주요 일정 기록
- 마감 임박 및 마감 공고 구분
- 원문 출처, 원문 링크, 마지막 확인 시각 표시
- 활성 공고와 종료·확인 불가 공고 구분

### 4.2 MVP 제외 범위

- 채용 사이트 전체를 주기적으로 순회하는 전면 자동 수집
- 채용 플랫폼의 유료·비공개 정보 복제
- 기업 리뷰, 연봉, 면접 후기의 자체 수집 및 재배포
- 여러 사용자 가입, 공유, 협업, 관리자 기능
- 이력서 작성 및 입사지원서 자동 제출
- AI가 지원 여부를 대신 결정하는 단일 적합도 점수
- 모바일 전용 앱
- 채용 플랫폼을 대체하는 자체 공고 게시 기능

### 4.3 후속 확장 후보

- 사용자가 지정한 검색 조건에 따른 신규 공고 자동 발견
- 공식 제공 방식이 있는 출처와의 연동
- 공고 본문 변경 및 종료 감지
- 이메일 또는 캘린더 알림
- 이력서와 공고 간 근거 기반 적합 요소 분석
- 기업별 외부 리뷰·연봉 페이지 연결
- 계정, 기기 간 동기화, 다중 사용자 공개 서비스

## 5. 사용자와 주요 시나리오

### 사용자

초기 사용자는 여러 채용 플랫폼을 탐색하며 본인의 취업 또는 이직 공고를 관리하는 단일 개인 사용자다.

### 시나리오 1: 발견한 공고 저장

**우선순위**: P1
**독립 검증**: 유효한 공고 URL 하나를 등록하고 목록과 상세 화면에서 저장 결과를 확인한다.

1. 사용자가 다른 채용 사이트에서 공고를 발견한다.
2. 사용자가 원문 URL을 등록한다.
3. 도구는 확인 가능한 핵심 정보를 채우고, 확인하지 못한 필드는 비어 있음을 명확히 표시한다.
4. 사용자는 저장 전에 정보를 검토·수정한다.
5. 저장된 공고가 통합 목록에 나타난다.

**인수 시나리오**

- 유효한 URL을 등록하면 출처와 원문 링크를 포함한 공고가 저장된다.
- 정보를 일부 확인하지 못해도 사용자가 직접 보완하여 저장할 수 있다.
- 같은 URL이 이미 저장되어 있으면 새 공고를 만들기 전에 기존 공고를 안내한다.
- 접근할 수 없는 URL이면 실패 이유와 수동 등록 선택지를 보여준다.

### 시나리오 2: 공고 탐색 및 비교

**우선순위**: P1
**독립 검증**: 30개 이상의 서로 다른 공고에서 조건에 맞는 항목을 검색·필터링하고 원문으로 이동한다.

1. 사용자가 통합 공고 목록을 연다.
2. 키워드와 조건을 조합해 후보를 좁힌다.
3. 핵심 조건과 마감일을 목록에서 비교한다.
4. 상세 내용을 확인하거나 원문으로 이동한다.

**인수 시나리오**

- 회사명, 공고 제목, 직무 관련 키워드로 검색할 수 있다.
- 지역, 경력, 고용형태, 상태, 출처, 마감 여부로 필터링할 수 있다.
- 최신 등록, 마감 임박, 최근 게시 기준으로 정렬할 수 있다.
- 적용 중인 조건을 확인하고 한 번에 초기화할 수 있다.
- 정보가 없는 필드는 추정값처럼 보이지 않게 `정보 없음`으로 구분된다.

### 시나리오 3: 중복 공고 정리

**우선순위**: P1
**독립 검증**: 동일 회사·유사 제목·유사 기간의 공고 두 개를 등록하여 중복 후보 표시와 묶음 조회를 확인한다.

1. 도구가 기존 공고와 유사한 새 공고를 발견한다.
2. 사용자는 중복 후보와 판단 근거를 확인한다.
3. 사용자는 동일 공고로 묶거나 서로 다른 공고로 유지한다.
4. 묶인 공고에서도 각 출처의 원문 링크는 유지된다.

**인수 시나리오**

- 중복 후보는 자동 삭제되거나 자동 병합되지 않는다.
- 사용자가 중복 판단을 취소하거나 변경할 수 있다.
- 한 출처의 공고가 종료되어도 다른 출처 링크와 사용자 기록은 유지된다.

### 시나리오 4: 지원 과정 관리

**우선순위**: P1
**독립 검증**: 공고 하나를 관심 상태에서 지원 완료와 결과 기록까지 이동시킨다.

1. 사용자가 공고를 관심 대상으로 저장하거나 제외한다.
2. 지원하기로 결정하면 진행 상태를 변경한다.
3. 사용자는 메모와 다음 일정을 기록한다.
4. 도구는 현재 상태와 상태 변경 이력을 보여준다.

**인수 시나리오**

- 공고 상태를 `검토 전`, `관심`, `지원 예정`, `지원 완료`, `전형 진행`, `최종 합격`, `불합격`, `제외` 중 하나로 지정할 수 있다.
- 상태를 변경해도 메모, 일정, 원문 링크가 사라지지 않는다.
- 실수로 상태를 변경한 경우 이전 상태로 다시 변경할 수 있다.
- 제외한 공고는 기본 목록에서 숨기되 별도 조건으로 다시 찾을 수 있다.

### 시나리오 5: 마감 및 공고 유효성 확인

**우선순위**: P2
**독립 검증**: 마감일이 오늘, 임박, 경과, 미정인 공고를 각각 등록하여 표시를 확인한다.

1. 사용자가 목록에서 마감 임박 공고를 확인한다.
2. 마감된 공고는 활성 공고와 시각적으로 구분된다.
3. 원문을 확인할 수 없거나 내용이 종료된 경우 상태가 기록된다.

**인수 시나리오**

- 마감일이 있는 공고는 남은 기간 또는 마감 여부를 보여준다.
- 상시채용과 마감일 미정은 서로 구분한다.
- 마감되거나 원문 확인이 불가능해도 사용자 지원 기록은 보존한다.

## 6. 기능 요구사항

- **FR-001**: 사용자는 원문 URL을 입력하여 공고 등록을 시작할 수 있어야 한다.
- **FR-002**: 사용자는 제목, 회사명, 직무, 주요 내용, 자격요건, 우대사항, 경력, 학력, 고용형태, 근무지역, 급여, 기술·역량 키워드, 게시일, 마감일을 직접 입력하거나 수정할 수 있어야 한다.
- **FR-003**: 도구는 각 공고의 출처 이름, 원문 URL, 최초 등록 시각, 마지막 확인 시각을 보존해야 한다.
- **FR-004**: 동일 URL이 이미 존재하면 중복 저장 전에 기존 공고를 안내해야 한다.
- **FR-005**: 도구는 회사명, 제목, 직무, 근무지역, 게시 기간 등 확인 가능한 정보를 토대로 유사 공고 후보를 표시해야 한다.
- **FR-006**: 사용자는 중복 후보를 동일 공고로 묶거나 별개로 유지할 수 있어야 한다.
- **FR-007**: 중복으로 묶은 이후에도 모든 출처와 원문 URL을 확인할 수 있어야 한다.
- **FR-008**: 사용자는 회사명, 제목 및 직무 관련 키워드로 저장된 공고를 검색할 수 있어야 한다.
- **FR-009**: 사용자는 지역, 경력, 고용형태, 사용자 상태, 출처, 마감 상태로 공고를 필터링할 수 있어야 한다.
- **FR-010**: 사용자는 등록일, 게시일, 마감 임박 순으로 공고를 정렬할 수 있어야 한다.
- **FR-011**: 목록은 최소한 제목, 회사명, 직무, 지역, 경력, 고용형태, 마감일, 출처, 사용자 상태를 비교 가능한 형태로 표시해야 한다.
- **FR-012**: 확인되지 않은 값과 실제로 조건이 없는 값을 구분해 표시해야 한다.
- **FR-013**: 사용자는 공고별 지원 진행 상태를 정의된 상태 중 하나로 변경할 수 있어야 한다.
- **FR-014**: 사용자는 공고별 개인 메모와 다음 행동 일정을 작성·수정·삭제할 수 있어야 한다.
- **FR-015**: 도구는 공고별 상태 변경 시각과 변경 내용을 확인할 수 있게 보존해야 한다.
- **FR-016**: 사용자는 공고를 제외 처리하고, 기본 목록에서 숨기며, 필요할 때 다시 조회할 수 있어야 한다.
- **FR-017**: 도구는 마감일 경과, 마감 임박, 상시채용, 마감일 미정을 구분해야 한다.
- **FR-018**: 원문이 종료되거나 확인 불가능해져도 저장된 공고 정보와 사용자 활동 기록을 보존해야 한다.
- **FR-019**: 외부 페이지에서 정보를 가져오지 못한 경우 실패 이유를 이해할 수 있는 안내와 수동 입력 경로를 제공해야 한다.
- **FR-020**: 사용자가 저장·수정·상태 변경·중복 판단을 수행한 결과는 화면을 다시 열어도 유지되어야 한다.
- **FR-021**: 사용자 데이터 전체를 일반적으로 재사용 가능한 파일 형태로 내보낼 수 있어야 한다.
- **FR-022**: 사용자는 내보낸 데이터를 이용해 자신의 공고 및 지원 기록을 복원할 수 있어야 한다.

## 7. 핵심 데이터 개체

### 채용공고

회사, 직무, 근무조건, 요구조건, 게시·마감 정보 및 사용자 판단의 기준이 되는 표준화된 공고 단위다.

### 공고 출처

공고가 발견된 플랫폼 또는 기업 페이지, 원문 URL, 출처별 게시 상태와 확인 시각을 나타낸다. 하나의 채용공고가 여러 출처를 가질 수 있다.

### 중복 그룹

동일한 채용 기회를 나타낸다고 사용자가 확정한 여러 공고 또는 출처의 묶음이다. 자동으로 제안될 수 있지만 최종 판단은 사용자가 한다.

### 지원 활동

관심·지원·전형·결과 상태, 상태 변경 이력, 개인 메모 및 다음 행동 일정을 포함한다.

### 수집·확인 결과

원문 접근 성공 여부, 마지막 확인 시각, 확인할 수 없었던 정보와 그 사유를 나타낸다.

## 8. 예외 및 경계 사례

- 로그인이 필요하거나 접근을 제한하는 원문 URL
- 삭제, 리디렉션 또는 주소가 변경된 공고
- 이미지나 첨부파일에만 주요 내용이 있는 공고
- 회사명이 약칭·계열사명·영문명으로 서로 다르게 표시된 중복 공고
- 제목은 같지만 근무지나 채용 직군이 다른 공고
- 제목은 다르지만 실제 업무와 모집 기간이 같은 공고
- 여러 지역을 동시에 모집하는 공고
- 채용 시 마감, 상시채용, 마감일 연장 공고
- 급여가 범위, 협의, 회사 내규 등으로 표현된 공고
- 게시일 또는 마감일이 없는 공고
- 같은 URL의 내용이 이후 다른 채용공고로 교체된 경우
- 이미 지원한 공고가 종료되거나 중복 그룹에서 분리되는 경우
- 잘못된 중복 판단을 사용자가 되돌리는 경우

## 9. 성공 기준

- **SC-001**: 사용자는 발견한 공고 하나를 2분 이내에 등록하고 목록에서 확인할 수 있다.
- **SC-002**: 100개 이상의 저장된 공고에서 원하는 조건의 후보 목록을 30초 이내에 찾을 수 있다.
- **SC-003**: 핵심 정보가 확인 가능한 공고의 90% 이상에서 회사명, 제목, 출처, 원문 링크가 정확히 표시된다.
- **SC-004**: 동일 URL의 중복 저장은 시험 사례의 100%에서 사용자에게 사전 안내된다.
- **SC-005**: 명백히 동일한 공고로 구성된 시험 사례의 80% 이상이 중복 후보로 제시되며, 서로 다른 공고는 사용자 확인 없이 합쳐지지 않는다.
- **SC-006**: 사용자는 3번 이하의 주요 조작으로 공고의 관심 또는 지원 상태를 변경할 수 있다.
- **SC-007**: 마감일이 알려진 시험 공고의 100%가 임박·마감 여부에 맞게 분류된다.
- **SC-008**: 원문 확인 실패나 일부 정보 누락이 발생해도 사용자는 수동 입력을 통해 공고 등록을 완료할 수 있다.
- **SC-009**: 저장된 공고와 지원 기록을 내보내고 복원하는 시험에서 사용자 작성 정보가 100% 유지된다.
- **SC-010**: 사용자가 일주일간 실제 구직 활동에 사용했을 때 “여러 사이트에서 본 공고를 다시 찾고 상태를 기억하는 부담이 줄었다”고 평가한다.

## 10. 가정

- 초기 버전은 한 명이 개인 장치에서 사용하는 도구다.
- 사용자가 직접 발견한 공고 URL을 등록하는 방식이 MVP의 기본 유입 경로다.
- 외부 사이트 정보의 접근 가능 범위는 각 출처의 이용 조건과 공개 범위에 따른다.
- 자동 확인이 불가능한 정보는 추정하지 않고 사용자가 직접 입력할 수 있게 한다.
- 중복 판정 오류의 비용이 크므로 자동 병합보다 사용자 확인을 우선한다.
- 원문이 사라지더라도 사용자가 작성한 지원 기록은 장기적으로 가치가 있다.
- 공개 서비스 전환 시 계정, 개인정보 보호, 서비스 운영 정책, 출처별 이용 조건을 별도 기능과 운영 요구사항으로 정의한다.

## 11. 의존성과 제약

- 외부 출처의 페이지 구조, 접근 정책, 로그인 요구 및 이용 조건에 따라 가져올 수 있는 정보가 달라질 수 있다.
- 출처에서 제공하지 않거나 명확하지 않은 정보의 정확성은 보장할 수 없다.
- 공고 원문 내용과 게시 상태의 최종 기준은 해당 출처 페이지다.
- MVP는 원문을 대체해 재게시하는 서비스가 아니라 사용자의 개인적 탐색과 지원 관리를 돕는 도구다.

## 12. 단계 종료 조건

다음 조건을 모두 만족하면 MVP 요구사항 정의가 완료된 것으로 본다.

- P1 사용자 시나리오가 모두 독립적으로 검증 가능하다.
- FR-001부터 FR-022까지 구현 여부를 객관적으로 판정할 수 있다.
- 성공 기준을 실제 공고 표본과 사용자 작업으로 검증할 수 있다.
- MVP 포함·제외 범위가 명시되어 추가 아이디어가 후속 범위로 분리된다.
- 구현 계획 단계에서 추가 제품 범위 결정을 요구하는 미해결 항목이 없다.
