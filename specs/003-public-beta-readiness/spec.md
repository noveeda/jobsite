# Feature Specification: 공개 베타 준비

**Feature Branch**: `codex/initial-implementation`
**Created**: 2026-08-07
**Status**: Ready for implementation
**Input**: 기존 개인용 채용공고 허브를 다른 사용자가 안전하게 가입·사용·탈퇴할 수 있는 공개 베타 수준으로 준비한다.

## Scope

### In Scope

- 약관·개인정보 처리방침 공개, 필수 동의 및 버전 기록
- 본인 계정과 모든 사용자 소유 데이터를 삭제하는 탈퇴
- 운영 상태 확인, 안전한 로그, 요청 제한, 보안 응답 정책
- 외부 출처 필수 표기와 원문 우선 안내
- 운영 설정 검증과 배포·백업·복구·장애 대응 절차

### Out of Scope

- 결제, 관리자 콘솔, 고객지원 티켓, 네이티브 앱
- 승인받지 않은 자동 수집 또는 접근 제한 우회
- 외부 API 승인과 실제 자격 증명 발급
- 대규모 트래픽 최적화

## User Scenarios & Testing

### User Story 1 - 고지에 동의하고 시작 (Priority: P1)

신규 사용자는 처리 데이터와 외부 출처 조건을 확인하고 명시적으로 동의한 뒤 자신의 공고 공간을 사용한다.

**Why this priority**: 공개 서비스에서 개인정보 처리 고지와 동의는 출시 전 필수다.

**Independent Test**: 새 계정으로 로그인하여 최신 고지를 확인·동의하고 대시보드 진입을 검증한다.

**Acceptance Scenarios**:

1. **Given** 최신 동의가 없는 로그인 사용자, **When** 대시보드에 접근하면, **Then** 동의 화면으로 이동한다.
2. **Given** 사용자가 두 고지를 확인하고 동의했을 때, **When** 제출하면, **Then** 버전과 시각이 기록되고 대시보드에 진입한다.
3. **Given** 고지 버전이 변경됐을 때, **When** 기존 사용자가 접속하면, **Then** 재동의를 요구한다.

---

### User Story 2 - 계정과 데이터 삭제 (Priority: P1)

사용자는 삭제 범위를 확인하고 재확인한 뒤 자신의 계정과 데이터를 영구 삭제한다.

**Why this priority**: 데이터 삭제와 사용자 통제는 프로젝트 헌법의 공개 배포 조건이다.

**Independent Test**: 데이터가 있는 계정을 삭제하고 사용자 소유 행과 로그인 세션이 사라지는지 검증한다.

**Acceptance Scenarios**:

1. **Given** 로그인 사용자, **When** 정확한 확인 문구 없이 요청하면, **Then** 아무 데이터도 삭제되지 않는다.
2. **Given** 확인 문구를 입력했을 때, **When** 탈퇴가 성공하면, **Then** 데이터와 인증 계정이 삭제되고 로그인 화면으로 이동한다.
3. **Given** 삭제가 실패했을 때, **When** 요청이 끝나면, **Then** 실패를 숨기지 않고 재시도 안내를 제공한다.

---

### User Story 3 - 신뢰할 수 있는 베타 운영 (Priority: P1)

사용자는 남용과 장애가 격리된 서비스를 사용하고 운영자는 민감정보 없이 상태와 오류를 확인한다.

**Why this priority**: 운영 가시성과 남용 방어 없이는 공개 배포 후 피해를 통제할 수 없다.

**Independent Test**: 상태 확인, 요청 제한, 보안 헤더와 로그 안전성을 자동 검증한다.

**Acceptance Scenarios**:

1. **Given** 정상 운영 중, **When** 상태를 요청하면, **Then** 서비스와 저장소 상태를 2초 안에 확인한다.
2. **Given** 한 사용자가 제한 작업을 반복할 때, **When** 허용량을 넘으면, **Then** 다른 계정에 영향 없이 재시도 시각과 함께 거절된다.
3. **Given** 서버 오류 발생, **When** 로그가 생성되면, **Then** 요청 식별자와 오류 분류만 남고 토큰·키·사용자 내용은 남지 않는다.

---

### User Story 4 - 외부 출처를 오인 없이 확인 (Priority: P2)

사용자는 외부 API 정보의 제공 출처와 원문을 보고 저장 정보가 원문을 대체하지 않음을 이해한다.

**Why this priority**: 출처 표시는 외부 API 조건이자 프로젝트 헌법의 필수 원칙이다.

**Independent Test**: 사람인 API 공고와 수동 공고에서 표기, 원문 링크와 제공 방식을 검증한다.

**Acceptance Scenarios**:

1. **Given** 사람인 API 공고, **When** 목록이나 상세를 보면, **Then** 사람인 제공 표기와 원문 링크가 보인다.
2. **Given** 비활성 API 출처, **When** 등록하면, **Then** 수동 입력 상태가 표시된다.

### Edge Cases

- 동의 저장 중 연결이 끊기면 대시보드를 열지 않고 재시도한다.
- 동시 탈퇴 요청은 중복 삭제 없이 안전하게 끝난다.
- 운영 설정 누락은 정상처럼 숨기지 않고 누락 항목을 알린다.
- 요청 제한 저장소 실패 시 외부 호출 같은 위험 작업은 거절한다.
- 외부 API 실패는 사용자 기록을 변경하거나 삭제하지 않는다.

## Requirements

### Functional Requirements

- **FR-001**: 최신 필수 고지에 동의하기 전 개인 화면에 진입하지 못해야 한다.
- **FR-002**: 사용자별 고지 버전과 동의 시각을 보존해야 한다.
- **FR-003**: 약관·개인정보 처리방침·출처 안내는 로그인 없이 접근 가능해야 한다.
- **FR-004**: 사용자는 명시적 재확인 후 인증 계정과 모든 사용자 소유 데이터를 삭제할 수 있어야 한다.
- **FR-005**: 탈퇴는 인증된 본인만 수행하며 실패 여부를 숨기지 않아야 한다.
- **FR-006**: 공개 상태 확인은 비밀정보 없이 서비스와 저장소 준비 상태를 제공해야 한다.
- **FR-007**: 외부 호출·데이터 변경 중 남용 위험 작업에 사용자별 요청 제한을 적용해야 한다.
- **FR-008**: 로그에서 토큰, 키, 쿠키, 메모와 공고 본문을 제외해야 한다.
- **FR-009**: 클릭재킹, MIME 추론과 과도한 참조 정보 노출을 완화하는 응답 정책을 적용해야 한다.
- **FR-010**: 운영 설정 누락 시 정상처럼 시작하지 말고 원인을 식별할 수 있어야 한다.
- **FR-011**: 배포, 마이그레이션, 백업, 복구, 장애 대응과 롤백 절차를 문서화해야 한다.

### Source & Data Trust Requirements

- **DT-001**: 외부 정보의 출처, 원문 URL, 관찰 시각과 제공 방식을 보존해야 한다.
- **DT-002**: 외부 값, 정규화 값, 사용자 입력과 미확인 값을 구분해야 한다.
- **DT-003**: 사람인 API 정보에 필수 제공자 표기와 원문 우선 안내를 보여줘야 한다.
- **DT-004**: 승인·자격 증명이 없는 출처는 호출 없이 수동 입력으로 유지해야 한다.

### User Control & Recovery Requirements

- **UR-001**: 탈퇴 전 핵심 데이터를 내보낼 수 있어야 한다.
- **UR-002**: 탈퇴의 비가역성을 고지하고 별도 확인 문구를 요구해야 한다.
- **UR-003**: 출처 실패와 요청 제한은 기존 사용자 기록을 바꾸거나 삭제하지 않아야 한다.

### Key Entities

- **동의 기록**: 사용자, 고지 버전과 동의 시각
- **요청 사용량**: 사용자, 제한 작업, 시간 구간과 사용 횟수
- **운영 이벤트**: 비밀을 제외한 요청 식별자, 분류, 시각과 결과

## Success Criteria

### Measurable Outcomes

- **SC-001**: 신규 사용자는 2분 안에 동의 후 첫 대시보드에 진입한다.
- **SC-002**: 탈퇴 후 1분 안에 재로그인이 불가능하고 사용자 소유 데이터가 0건이다.
- **SC-003**: 정상 상태 확인의 95%가 2초 안에 응답한다.
- **SC-004**: 제한 요청 100건 시험에서 허용량 이후 모두 거절되고 다른 계정 허용량은 변하지 않는다.
- **SC-005**: 보안 검사에서 운영 응답과 로그에 등록된 비밀값이 노출되지 않는다.
- **SC-006**: 핵심 여정과 운영 검증이 Windows와 Ubuntu에서 통과한다.

## Assumptions

- 무료 공개 베타로 수십~수백 사용자, 계정당 수천 공고 이하를 대상으로 한다.
- 기존 Google 로그인, RLS, 내보내기·복원을 재사용한다.
- 법적 문안 초안을 제공하되 출시 전 운영자 정보와 최종 문안을 확정한다.
- 외부 API 자격 증명은 서버 환경에만 저장한다.

## Dependencies & Constraints

- 운영 Supabase, Google OAuth 클라이언트와 공개 HTTPS 배포 주소가 필요하다.
- 사람인 자동 연동은 승인된 access-key와 이용 조건 준수가 필요하다.
- 출시 전 운영자명, 개인정보 문의 연락처와 고지 시행일을 확정해야 한다.
- 인증 계정 삭제용 관리 자격 증명은 클라이언트에 노출할 수 없다.
